## 4. 启动隔离的 trained/random 服务

## 5. 真实 MCTS + TTT

核心实现：

- `cpu_runtime/online_ttt.py`：同树搜索、learn barrier、参数变化和版本消费验证。
- `gpu_runtime/categorical_search_backend.py`：64 档距离头推理及搜索接入。
- `gpu_runtime/real_backend.py`：REAL7B policy、LoRA 和会话状态。
- `experiments/proof-curriculum/runner/course_driver.py`：课程状态机、意图/证据、发布与退役。

冻结难题 H1 使用 `48 checkpoints / 1800 s / max 4 learns`。同题 trained/random 预算完全一致；完整 pair 后才进入下一题。每次运行保存 create、generation、Lean eval、selection、backup、learn、snapshot、retire 原始回执。任何未知 mutation 都停下审计，不换 ID 重发。

REAL7 full-v3 每次 learn 联合更新 LoRA 与 categorical value head，并核对两者及 optimizer 的变化；有效 `search_visit_backup` 给出有限距离 target，裁剪到 `[1,64]` 后用相邻档 two-hot categorical cross entropy。更新提交后还必须完成 selection-value refresh barrier，再确认新版本被 generation 消费。S18 外部 critic 路线才是冻结 critic 的 policy-only learn。复现报告不得把两种合同混写。

通用课程的真实 CLI、runtime JSON 字段和外部验收交换步骤见：

`.downloads/new-value-head-20260829/radeon-fullv3-handoff/runtime-code/experiments/proof-curriculum/runner/README.md`

最小顺序为：`prepare -> preflight -> approval-template -> run --authorize-remote --max-lessons 1`。每次再次运行只推进下一课，不自动跳过未知状态。
