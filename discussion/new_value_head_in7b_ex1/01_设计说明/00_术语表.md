# 术语表

## 模型与价值

**Policy（策略模型）**：根据当前 Lean proof state 生成下一条 tactic 候选。这里的主体是 REAL-Prover 7B。

**Value head（价值头）**：读取冻结模型的状态表征，预测该状态距离证明完成还有多远。它不直接生成 tactic。

**Remaining distance / `d`（正剩余距离）**：从非终态到已知证明终点的剩余步数估计。本项目裁剪为 `1..64`；越小越好。

**Search value / `V=-d`（搜索效用）**：MCTS 要最大化数值，所以把距离在接口处变号。`d=2` 的状态比 `d=10` 更有希望，因为 `-2 > -10`。

**Categorical value head（分档价值头）**：不直接输出一个 scalar，而是输出 64 个距离档的 logits。softmax 后对档位取期望得到 `d`。

**Two-hot target（相邻双档目标）**：当在线 target 是小数时，把概率质量按比例放到相邻两个整数档，而不是粗暴四舍五入。

**Exact matched-random（精确随机同构对照）**：与 trained head 使用相同结构、seed 和训练前初态，但不做离线训练。它用于判断改进来自学到的 value，而不是结构或随机差异。

## 搜索

**MCTS（Monte Carlo Tree Search，蒙特卡洛树搜索）**：反复选择树中节点、扩展 policy 候选、用 Lean 验证并回传价值的搜索方法。

**PUCT**：MCTS 中结合已访问价值与 policy 先验的选择公式；决定当前预算下一步探索哪个分支。

**Selection（选择）**：根据 PUCT/value 从已有树中选择要继续扩展的路径。

**Revisit（回访）**：再次选择已存在的状态或分支。正确 value 应把预算重复投入真正有希望的关键状态，而不是只追求更多节点。

**Backup（回传）**：把子节点的搜索结果沿路径更新到祖先节点/边，使后续 selection 能使用这些证据。

**合法非重复后继**：tactic 经 Lean 接受，且产生未在当前树中重复出现的新 proof state。字符串新颖不等于合法推进。

**Dead node（死节点）**：已经形式化确认不可能继续的节点，才允许记为 `-∞`。预算用完或暂时没找到证明只是 unknown。

## 训练与运行

**LoRA**：在冻结大模型旁增加的小型低秩可训练参数。本项目题内更新 policy LoRA，不改冻结 base 权重。

**TTT（Test-Time Training，测试时训练）**：模型在解决当前题时，用该题真实搜索轨迹做在线更新，再继续解决同一题。

**联合 TTT**：REAL7B full-v3 的一次在线 learn 同时更新 policy LoRA 和 categorical value head，并更新 optimizer state。

**Policy version（策略版本）**：每次成功 learn 后递增。只有新版本被后续 generation/value 请求实际使用，才证明更新进入了搜索闭环。

**Selection-value refresh（旧节点价值刷新）**：learn 后重算树中已有节点的缓存 value。本成功案例的 stable runtime 关闭该功能；新生成状态使用新版本，但旧节点缓存不重算。

**Checkpoint**：搜索在一个可审计边界写出的状态快照/进度记录，不等同于模型权重 checkpoint。

## 课程与证据

**Curriculum（课程）**：针对失败前沿暴露的最小能力缺口设计的较易题，目的是训练一个真实证明接口，不是把原题答案拆给模型。

**Student theorem（学生定理）**：模型自己生成、经独立 Lean 验收并封存的课程证明。后续原题可以显式使用它，但必须标注为定理库辅助。

**Experience**：成功 session 发布的不可变训练/证明经验，包含权重、来源、proof 与验收 lineage，供 fresh session 继承。

**Lineage（谱系绑定）**：证明新 session 精确继承了哪份 experience、weights、snapshot 和源版本，防止混用旧树或不明参数。

**Seal / Publish / Retire**：依次表示封存 session 状态、发布可继承 experience、释放并终止该 session。成功 proof 本身不等于发布已完成。

**Independent Lean acceptance（独立 Lean 验收）**：在固定 CPU 镜像、禁网环境中重新编译完整 proof，并检查类型与公理。只有通过它才称完整证明成功。

**Matched pair（匹配配对）**：trained 与 random 两臂使用相同题面、policy/LoRA 初态、空 optimizer、RNG、预算和 Lean 环境，以支持因果比较。
