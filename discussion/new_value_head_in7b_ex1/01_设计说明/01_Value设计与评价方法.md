# 设计说明

## 1. 要学习什么

AlphaProof 风格的 value 不是“这个状态看起来好不好”的无标度分数，而是到已知证明终点的剩余步数。训练标签为裁剪后的 `d∈[1,64]`；证明终态单独定义为 `d=0`。搜索需要最大化效用，所以只在接口边界做一次符号变换 `V=-d`。

这种定义有三个优点：数值可解释；不同状态可以按“更接近证明”排序；搜索日志可直接核对头输出、分支选择和 backup 是否方向一致。它也有明确局限：训练树中的最短已知距离不等于全局最短证明，64 档裁剪削弱长距离区分，分布外题可能严重失准。

## 2. 数据与防泄漏

- train：205,628 个 LeanTree 状态，其中原 80,000 与新增 125,628 都绑定来源 manifest。
- validation/test：各 8,000，测试只读一次。
- train/validation/test 在 sample、state、root、theorem family 四个层面隔离。
- 80k 头只保留为历史消融，不进入正式实验。

冻结 REAL7B encoder 对每个状态生成 3584 维特征。只训练小头，避免把 base/policy 的变化与 value 学习混在一起，并让精确随机同构对照可实现。

## 3. 模型与损失

正式 full-v3 结构是 `3584 -> 256 -> 64`，中间使用 SiLU，输出 64 档 logits；监督目标是距离档位的交叉熵。推理时对 softmax 分布在 `{1,...,64}` 上取期望得到 `d`。随机对照来自同一初始化 seed、同结构且未经离线训练的初态，不是另一个随意随机头。

离线门同时看 NLL/MAE、根内排序和公共 pair；这些指标只证明“学到了一些距离结构”，不能代替端到端证明评测。

## 4. 接入 MCTS

每个合法后继都保存 `raw_distance=d` 与 `search_value=-d`。PUCT/backup 只消费后者。审计至少记录：

- 相同 policy RNG 下候选文本、顺序和 logprob 是否一致；
- Lean disposition、合法且非重复的后继集合；
- value 改变了哪个 selection、回访次数和分支预算；
- backup 的节点/边/版本；
- 最终证明是否来自被 value 提升的关键后继。

“full-v3 的数值更像真实距离”本身不算帮助。D1 就是反例：两臂距离尺度差异巨大，但整条搜索轨迹相同，因此判为 value 无可辨认作用。

## 5. 课程学习与 TTT

课程由审核后的固定单族、固定顺序构成，最后一个成员才是原目标。课程数量由可审计能力缺口决定，不机械限制门数。学生侧看不到教师证明；课程关系是教学依赖，不是假装成逻辑蕴含。每课使用独立 session；只有独立 Lean 成功且确有有效更新时，才允许发布经验给下一课。

成功子课还可以进入累积学生定理库：必须保存模型自己生成的完整 proof、声明 type、source SHA、独立 Lean 与公理检查，并完成 success-learn、不可变 experience 发布和下一 session lineage 核对；之后才把该声明及学生 proof 加入后续可见输入。原题可以调用这些已验证定理，但报告必须单列“参数迁移”和“显式定理库辅助”，不能把后者伪装成纯 TTT 泛化。

REAL7 full-v3 的题内 TTT 将 policy LoRA 与 categorical value head 共同放入 optimizer 并联合更新；必须分别核对 adapter、value head 与 optimizer 的真实变化。S18 使用外部冻结 critic/encoder/head，题内只更新 policy。两者都要求 learn 请求有真实轨迹、policy version 递增，并由之后至少一次 generation 实际消费新版本。预算耗尽的题不发布为成功经验。

REAL7 的在线 value target 不是把“失败”写成负无穷，而是从有效 OR 节点的 `search_visit_backup` 取有限回传距离。分数先裁剪到 `[1,64]`，小数距离投影到相邻两个档位，使用 two-hot categorical cross entropy；总更新同时包含 policy 项和对冻结 base policy 的 KL 约束。每次更新后必须重新刷新 selection value，避免旧 value 与新版本混用。

## 6. 与 AlphaProof 思路的对应及工程差异

对应关系：都把 value 解释为证明剩余长度的负值；都让搜索产生的真实轨迹反过来改进模型；都以形式系统验收而非自然语言自评作为成功门；课程由较容易的相关任务逐步走向目标题。

当前实现的工程化取舍：距离裁剪为 64 档；先在冻结 REAL7B 表征上离线训练小头，再在单题 TTT 中联合更新 LoRA 与头；训练信号只来自可审计 LeanTree 与本题 visit/backup；没有大规模 AlphaProof 式自博弈集群。因此本实验验证的是相同价值语义与闭环机制在当前硬件/数据条件下是否有效，不声称复刻 AlphaProof 全部系统。

当一条原题搜索耗尽时，不应直接把预算加大或跳到更难题。先完成 matched control，再从可审计 trace 判断缺的是候选生成、Lean 合法性、value 排序、回访/backup，还是在线更新没有改变后续候选。只有定位到明确技能缺口后，才从学生可见题面设计最小充分的不泄露课程，运行前固定顺序，最后回到原题。失败轨迹不发布为成功经验。

允许有审计的提前早停，但不能凭“暂时没证明”干预：除工程/unknown、非有限 value 或合同错误外，至少等待 16 checkpoints、2 次联合 learn 被后续 generation 消费，并观察连续两个完整更新窗口。只有最深残式不变、无新合法非重复节点、候选持续重复/非法且没有未访问的高分有效候选时才建议在 checkpoint 安全边界停；若刚出现新结构、闭合子目标或首次正确定理调用，必须继续一个有界窗口。

## 7. 怎样判定“最好”和“够好”

相对选择顺序：完整证明数与独立 Lean -> value 导致的关键合法后继/正确回访 -> 跨题稳定性 -> 独占成本。墙钟只有在无共享负载、预算和顺序可比时才进入排名。

绝对可用门独立于相对名次：即使 full-v3 是本批最优，如果 20 题中只在一题偶然成功、持续误导预算或没有稳定关键后继收益，结论仍应是“当前最好但还不够好”。
