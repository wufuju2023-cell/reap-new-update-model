# F1：full-v3 真实 MCTS + TTT + 独立 Lean 成功案例

F1 是当前首个能把 value 的机制变化与完整证明联系起来的 matched causal pair。它不是首候选秒解：full-v3 经多轮选择、回访和 3 次题内联合更新后才在 checkpoint 31 闭合；因此适合作为第一份“有适当难度、完整框架跑通”的展示。

## 固定条件

- policy/base：同一 REAL-Prover 7B、同一 LoRA 构造与空 optimizer。
- value：trained full-v3 对 exact R64-v3 random initial。
- 数据：full-v3 来自 205,628 个 root/family 隔离训练状态。
- 预算：两臂 `32 checkpoints / 1200 s / max 4 learns`，顺序执行。
- 初始控制：首候选、原 policy、session RNG 与题面一致。

## 运行结果

| 项 | full-v3 | exact random |
|---|---:|---:|
| 搜索终态 | checkpoint 31 完整证明 | checkpoint 32 耗尽 |
| 题内有效 learn | 3，版本到 v3，后续 generation 消费 | 4，版本到 v4，后续 generation 消费 |
| 合法非重复节点 | 22 | 20 |
| raw distance mean | 2.9054 | 32.2840 |
| 关键存在状态回访 | 27 | 23 |
| 独占墙钟 | 185.952671 s | 239.325899 s |

墙钟仅作本 pair 记录；最终速度结论不能由单题给出。

## value 如何实际影响搜索

在同一个关键状态，两臂看到四个相同候选，访问数分别是：

```text
full-v3: [0, 7, 0, 1]
random:  [0, 4, 1, 3]
```

两臂都生成关键合法后继 `use f (t-c)`。full-v3 给该方向更高的搜索效用（更小 d，因此更大的 -d），持续回访该存在状态，随后生成两步 `simp` 并闭合；random 把更多预算分配给未完成的 `have` 分支，最终在相同预算内未闭合。

证据链因此是：相同 policy 候选 -> value 排序不同 -> selection/revisit 与 backup 预算不同 -> full 回到关键合法状态 -> 后续策略生成闭合动作 -> 完整证明。

## TTT 如何参与

REAL7 full-v3 的 online learner 将 policy LoRA 与 categorical value head 共同放入 AdamW。有效搜索 visit/backup 产生有限距离，裁剪到 64 档后用 two-hot categorical loss 更新头；policy 同时接受搜索目标和 KL 约束。证明前发生 3 次联合 learn：每次都有 adapter、value head、optimizer 的真实变化、policy version 递增，并在 selection-value refresh 后被同树 generation 消费。

证明成功后另有一次 v3→v4 terminal learn，目标距离 `4/3/2/1`；它发生在闭合以后且没有后续 generation，故单列保存，不能用于解释本次成功。

## 可复现入口

训练和服务合同按 [完整复现手册](../03_复现与代码/01_完整复现手册.md) 的 1–4 节重建；真实搜索复用 handoff runtime 中的 `cpu_runtime/online_ttt.py` 与 `gpu_runtime/categorical_search_backend.py`；独立验收按第 6 节执行。复现时必须同时运行 exact random matched arm，不能只重放成功臂后声称 value 因果。

## 结论边界

本例支持“full-v3 在 F1 上通过排序、回访和联合 TTT 帮助完成证明”。它不单独支持“full-v3 已是稳定默认”；后者仍由冻结 20 题矩阵决定。
