# 5. 复现方法

本案例分三层复现。只想理解或审核时运行第 A 层；有训练特征但没有 7B 服务时可运行第 B 层；具备相同模型、Lean 镜像和 GPU 服务时运行第 C 层。

## A. 核验随包文件

在案例目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\verify_bundle.ps1
```

它核对随包代码/配置/报告 SHA，并检查训练报告的模型结构、数据行数和 checkpoint identity。无需 GPU、网络或大模型。

恢复器的离线合同测试：

```bash
python -B -m unittest code/test_success_learn_recovery.py -v
```

## B. 从冻结特征重训 head

准备 Python、PyTorch/CUDA，并取得四组冻结特征：train80k、train extension 125628、validation8k、test8k。四组必须来自同一 frozen encoder fingerprint，并通过 sample/state/root/family 隔离门。

```bash
python3 -B code/train_value_head.py \
  --train-features "$TRAIN80K_FEATURES" \
  --train-extension-features "$TRAIN125628_FEATURES" \
  --validation-features "$VALIDATION8K_FEATURES" \
  --test-features "$TEST8K_FEATURES" \
  --output "$NEW_EMPTY_OUTPUT" \
  --device cuda:0 --seed 20260829 \
  --epochs 30 --patience 5 --batch-size 4096 \
  --learning-rate 1e-3 --weight-decay 0.01
```

要求输出 trained 与 exact-random 初态、训练报告和完成标记；trained checkpoint 应与本包报告的 SHA 对照。若特征内容不同，不能期待逐字复现同一 checkpoint，但必须重新记录数据/模型 fingerprint 和指标。

## C. 复现真实课程、MCTS 和 TTT

### C1. 外部依赖

- REAL-Prover 7B 冻结 base；
- trained full-v3 head；
- 与 `config/runtime-full-portable-v2.json` 同 schema 的平台本地合同；
- Lean/mathlib 固定 CPU 镜像；
- GPU categorical server、snapshot/experience/trusted-success 持久目录；
- 课程 driver 所需的其余仓库模块。

大工件不在本包内，需由复现者从其有权使用的模型/数据发布渠道另行取得；本包不提供不可访问的本机路径或伪下载地址。部署前仍必须为自己取得的工件生成 canonical tensor manifest，逐张量比较 base identity，核训练头身份，并通过 GET 获取本次部署的 runtime pin；不允许绕过 pin create。

### C2. 准备课程

使用 `config/ExecutionDeclarations.lean`、`config/initial-course.approved.json` 与 `config/initial-course-budget.json`。先在固定镜像中禁网编译声明，再用 `code/course_driver.py` 执行 `prepare -> preflight -> run --authorize-remote --max-lessons 1`。具体 CLI 参数由：

```bash
python3 code/course_driver.py --help
```

读取；不要复制本次 session nonce，也不要覆盖旧 store。新复现必须建立 fresh family/store/session。

### C3. 运行与验收门

1. GET 精确匹配 runtime contract pin 后 create。
2. 观察 checkpoint 连续增长；正常约 4–6 秒/step，8–16 步内不做行为干预。
3. 每次 learn 核 LoRA/head/optimizer 变化和 version 递增。
4. 下一个完整窗口核新 generation/value 消费新版本。
5. proof 出现后用 `code/VerifiedReplay.lean` 对接固定 CPU 镜像，`network=none` 独立验收。
6. success replay、terminal learn、seal、publish、snapshot、retire 逐项保存回执。

本次稳定合同为 `selection_value_refresh=false`。若新的 Lean runtime 已实现并验收 refresh producer，可在全新 family 中启用；不能只因为 Python consumer 存在就宣称支持。

## D. 可复现范围

随包可直接复现：代码与配置审计、训练报告合同检查、success-learn 恢复器单测。取得相同格式的冻结特征后可复现训练方法；取得兼容的 REAL-Prover 7B、Lean 环境和 GPU 服务后可复现端到端流程。由于本包不分发大模型、特征和快照，它不承诺读者仅凭此目录逐字重现同一个 checkpoint 或同一条随机搜索轨迹。

## E. 复现结论而非偶然成功

单臂复现验证的是流程。要验证 value 的相对作用，必须另开 exact R64-v3 matched arm，并固定题面、policy/LoRA 初态、空 optimizer、RNG、预算、Lean 环境与 arm 顺序；比较 selection/revisit/backup、合法非重复关键后继和独立 Lean 证明，而不是只比较 wall time 或 distance 尺度。
