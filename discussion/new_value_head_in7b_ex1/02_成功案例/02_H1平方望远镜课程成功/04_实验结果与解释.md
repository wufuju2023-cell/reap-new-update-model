# 4. 结果与解释

## 4.1 已经跑通的完整核心链

```text
205,628 隔离状态
→ 冻结 7B 表征训练 full-v3 64档 head
→ portable model/runtime identity 检查
→ 课程题上的真实 policy generation
→ Lean 过滤非法动作
→ d 转为 -d 参与 MCTS selection/backup
→ step 7 联合更新 LoRA+head
→ v1 被后续搜索消费
→ step 15 再次联合更新
→ v2 被后续搜索消费并得到完整 proof
→ 独立 Lean accepted
→ 成功轨迹 v2→v3 联合更新
```

这已经是可展示的真实成功，不是 toy、模拟器或本地伪造重放。

## 4.2 value head 在本例中的具体作用

value head 在每个合法非终态上预测正剩余距离；MCTS 使用负距离排序和回传。它还不是冻结旁路：两次题内训练和终端成功训练都更新了 categorical head，本次 terminal update 中 4/4 value 张量变化得到明确核验。更新后的 v1/v2 由后续新生成和新 value 前向消费，证明闭环接线真实生效。

但因为本例没有随机臂，不能把“最终成功”全部归因给 pretrained head；policy、搜索和在线学习共同构成结果。最严谨的表述是：full-v3 参与并完成了一条真实成功闭环，且其在线更新被证明前的搜索消费。

## 4.3 与随机头的客观背景

在独立的 F1 matched pair 中，full-v3 与 exact R64-v3 从相同 policy/RNG/预算出发；full-v3 增加关键存在状态回访并生成后续两步 `simp` 闭合，独立 Lean 成功，而随机臂失败。这提供“trained value 改变分支选择并带来证明”的正向因果证据。

其他 pair 也说明不能只挑成功故事：D1/D2 中两头虽数值尺度不同但搜索轨迹相同；P2/H1 中 value 改变预算或轨迹却没有证明。故当前结论仍是“full-v3 是最好的可执行候选，但完整 20 题前不能宣称已经稳定可靠”。

## 4.4 本课程对原 H1 的意义

课程成功证明模型在 full-v3+TTT 条件下能完成低一阶的相同结构接口。下一步不是继续刷类似平方题，而是：独立封存学生 proof 和 experience，在 fresh session 中核 optimizer step 0 与 lineage，把该已验证学生定理作为可见库成员，再回原立方 H1。只有原 H1 自己的完整 proof 通过独立 Lean，才能称原题成功。

## 4.5 收尾事故与恢复

terminal success-learn 已应用，但旧 validator 不认识后端新增的合法 `value_training` two-hot 审计字段。严格恢复器兼容旧 scalar、严格接纳合法 categorical 字段、拒绝 distance/target/prediction/bin/weight/saturation/nonzero 篡改，并在固定镜像禁网 dry-run 中证明 0 network calls、0 mutation calls。最终 commit 只补 completion，learn 绝未重发；原 driver 随后成功 seal、发布 `exp-078cea5460cb-01` 并 retire。这个事故不再是开放尾项，但作为 schema 演进必须 fail-closed 的工程教训保留。
