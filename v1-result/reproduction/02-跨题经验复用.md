# 跨题经验复用

本篇把第01篇新训练得到的参数用于另一道题：来源题完成更新并证明 → 独立Lean验收 → 发布不可变经验 → 新题复制策略适配器和价值头 → 核对参数、私有状态与新证明。

沿用第01篇的 `search_visit_backup` 训练目标、同一基座模型和 `gamma=0.99`。中央混合学习的模型发布使用另一套合同，本篇选择题内TTT产生的经验。

原实验中，Cube、Scaled、Affine三题继承同一经验后，分别更新4、1、1次并独立通过，见[跨题原始记录](../evidence/current/cross-problem/README.md)。下面使用自己的新会话和新验收记录，结果以新运行实测为准。

## 1. 保留已验收的来源题

先完成[环境与代码](00-环境与代码.md)和[单题TTT](01-单题TTT.md)。沿用CPU终端中的 `REPORT`、`RUN`、`CPU_IMAGE`、`GPU_URL`，以及第01篇复制到 `RUN/run_one.sh` 的启动脚本。

来源题需要至少一次真实更新，且更新后的参数被后续生成使用，最终证明通过独立Lean检查。第01篇已启用 `--experience-candidate`：满足这些条件时，CPU保存 `experience-candidate.json`，GPU保存同名完整快照并封存来源会话。独立验收生成 `proof-check/<来源ID>/accepted.json`。

保留来源会话以检查新题运行期间的隔离；第01篇GPU服务的驻留上限为2，足够同时保留来源题和新题。实际GPU快照、Adam状态及经验参数载荷不包含在交付包内，本篇从第01篇的新运行生成它们。

在CPU终端执行：

```bash
set -euo pipefail
: "${REPORT:?}" "${RUN:?}" "${GPU_URL:?}" "${CPU_IMAGE:?}"
export SOURCE_SID="$(cat "$RUN/source-session-id.txt")"
export PYTHONPATH="$RUN/source${PYTHONPATH:+:$PYTHONPATH}"
```

来源未经更新就证明时，可以保存其数学证明，但暂不进入本篇的训练经验发布流程。候选快照的会话身份、版本、完成标志都由实际运行产生。

## 2. 验收后发布一次，保存三个来源字段

辅助脚本会重新检查来源证明文件、原输入、搜索结果、独立容器退出状态、公理列表、日志SHA，以及候选快照对应的题目和版本。全部通过后，才向原GPU服务调用一次 `publish_experience`。

```bash
python3 -B "$REPORT/reproduction/scripts/cross_experience.py" publish \
  --run-root "$RUN" --session-id "$SOURCE_SID" \
  --gpu-url "$GPU_URL" --cpu-image "$CPU_IMAGE"

source "$RUN/cross/settings.sh"
cat "$RUN/cross/pins.json"
```

`RUN/cross/` 必须原先不存在；脚本先保存发布意图，再提交请求，最后保存原回执和固定字段。新经验ID与新题ID仅生成一次。服务器将验收声明绑定到确切来源快照；Lean验证已经在第01篇的独立容器中完成，服务器不会把声明重新当成一次数学检查。

新题需要三个字段：

- `experience_id`：本次不可变经验的名字。
- `experience_weights_sha256`：策略适配器、价值头及其合同的内容摘要。
- `experience_snapshot_sha256`：来源完整快照清单的摘要。

实际经验位于GPU的 `GPURUN/experiences/<经验ID>/release/`。来源版本保留在来源记录中；新题自己的更新计数从0开始。

如果发布超时，保留 `publish-intent.json`，不要再次执行发布命令或删除目录。先按[结果检查与故障处理](04-结果检查与故障处理.md)核查原请求和GPU经验目录；文件存在与否都不能单独授权重复提交。

## 3. 保存来源状态，再启动另一道题

在目标题开始前保存来源题完整状态：

```bash
python3 -B "$REPORT/reproduction/scripts/cross_experience.py" source-snapshot \
  --run-root "$RUN" --gpu-url "$GPU_URL" --phase before
printf '新题会话：%s\n' "$TARGET_SID"
```

若使用OpenCLI桥，先把这个新 `TARGET_SID` 加入桥的允许列表。继续使用原GPU服务和原来源会话。

新题选择 `03-ScaledTriangular.lean`：已知数列初值和递推式，目标是证明缩放后的三角数公式。输入由统一准备工具从原实验中提取，不含证明答案。执行：

```bash
set +e
bash "$RUN/run_one.sh" "$TARGET_SID" 03-ScaledTriangular.lean \
  --experience-id "$EXPERIENCE_ID" \
  --experience-weights-sha256 "$EXPERIENCE_WEIGHTS_SHA256" \
  --experience-snapshot-sha256 "$EXPERIENCE_SNAPSHOT_SHA256"
target_rc=$?
set -e
python3 - "$RUN" "$TARGET_SID" "$target_rc" <<'PY'
import json, pathlib, sys
run, sid, rc = pathlib.Path(sys.argv[1]), sys.argv[2], int(sys.argv[3])
print('目标题启动命令的原始退出码：', rc)
if rc != 0:
    report = json.loads((run / 'outputs' / sid / 'online-result.json').read_bytes())
    inspection, = json.loads((run / 'launches' / sid / 'container-inspect.json').read_bytes())
    state = inspection['State']
    saved_rc = int((run / 'launches' / sid / 'returncode.txt').read_text().strip())
    known_proof_without_update = (
        rc == saved_rc == 2
        and report.get('session_id') == sid
        and report.get('status') == 'solved_without_online_update'
        and report.get('root_verified') is True
        and 'error' in report and report['error'] is None
        and type(report.get('returncode')) is int and report['returncode'] == 0
        and type(state.get('ExitCode')) is int and state['ExitCode'] == 2
        and state.get('Running') is False
    )
    if not known_proof_without_update:
        raise SystemExit('目标运行失败或状态未知；保留记录并停止，不重跑同一ID。')
    print('已确认继承后零次更新完成证明；原退出码2保留，继续独立Lean检查。')
PY
```

GPU在分配新题前检查固定来源字段以及模型、训练目标、gamma和参数形状；CPU在启动Lean前再次核对创建回执。策略适配器和价值头来自经验，优化器、随机状态、缓冲区、更新计数和事件收据为新题独立初始化。来源会话保持封存。

启动脚本将原返回码保存到 `RUN/launches/$TARGET_SID/returncode.txt`。上面的包装保留该值：退出0按正常流程继续；退出2时，只有搜索报告与已停止容器共同确认 `solved_without_online_update`，才继续独立证明检查。这个结果表示继承后完成了证明，新增训练次数为0。其他失败、未证明或未知状态都会停止，不重启同一ID。

## 4. 独立检查新证明，再保存来源状态

只有新题有明确的成功搜索结果时执行独立Lean检查：

```bash
python3 -B "$REPORT/reproduction/scripts/extract_online_proof.py" \
  --run-root "$RUN" --session-id "$TARGET_SID" \
  --input-file 03-ScaledTriangular.lean \
  --theorem MultiroundCandidates.ScaledTriangular.scaled_triangular \
  --cpu-image "$CPU_IMAGE"

python3 -B "$REPORT/reproduction/scripts/cross_experience.py" source-snapshot \
  --run-root "$RUN" --gpu-url "$GPU_URL" --phase after
```

`after`命令要求目标题独立验收已完成，并把目标验收、输入和搜索结果的摘要写入快照意图；`before`命令要求目标输出尚不存在。两次来源快照因此覆盖目标题的实际运行窗口。

## 5. 在GPU主机上，用CPU检查实际参数

这里读取完整的可训练状态文件（附加参数、价值头及优化器等），使用Torch的CPU解码，不创建基座模型、不进行新训练，也不把7B权重下载到CPU电脑。检查包括：

- 来源候选 → 发布经验 → 新题 `before-online-ttt` 的适配器及价值头逐张量相等。
- 新题本地版本为0，优化器与缓冲区为空，随机种子来自新会话ID。
- 来源 `cross-source-before` 与 `cross-source-after` 的全部逻辑状态和实际参数、Adam、随机状态相等。

先在CPU终端制作小型检查包，仅包含两个辅助脚本和本次发布、快照回执：

```bash
test ! -e "$RUN/cross-check.tgz"
tar -czf "$RUN/cross-check.tgz" \
  -C "$REPORT/reproduction/scripts" cross_experience.py extract_online_proof.py \
  -C "$RUN" cross
sha256sum "$RUN/cross-check.tgz"
```

按第00篇选定的文件传输方式，把它上传为 `GPURUN/cross-check.tgz`。若使用SSH，可在CPU终端执行 `scp "$RUN/cross-check.tgz" "$GPU_SSH:$GPURUN/cross-check.tgz"`；其中 `GPU_SSH` 为自己的连接目标，CPU终端中的 `GPURUN` 需填写GPU实际路径。

在GPU终端先用 `sha256sum "$GPURUN/cross-check.tgz"` 核对与CPU打印值相同，再执行：

```bash
set -euo pipefail
mkdir "$GPURUN/cross-check"
tar -xzf "$GPURUN/cross-check.tgz" -C "$GPURUN/cross-check"
PYTHONPATH="$GPURUN/source" "$GPUPY" -B "$GPURUN/cross-check/cross_experience.py" check-tensors \
  --gpu-run-root "$GPURUN" --cross-dir "$GPURUN/cross-check/cross" \
  --output "$GPURUN/cross-check/tensor-audit.json"
cat "$GPURUN/cross-check/tensor-audit.json"
sha256sum "$GPURUN/cross-check/tensor-audit.json"
```

实际读取的是本次GPU目录的完整快照和经验载荷。所有检查通过才写 `passed: true`；输出已存在会拒绝覆盖。此处没有重新计算冻结7B基座的全量内容摘要，模型固定版本与运行合同沿用第00、01篇。

将新生成的 `tensor-audit.json` 下载为CPU的 `RUN/cross/tensor-audit.json`，核对SHA与GPU端打印值一致。证明验收与参数验收各自保留，不将一个结果代替另一个。

## 6. 保存产物并释放驻留会话

CPU端保存两题输出、两份独立证明，以及 `RUN/cross/` 中的发布、来源状态和张量检查结果。GPU持久目录保留快照与经验；之后其他新题仍可明确引用这份经验。

两题证明和张量检查全部通过后，下面命令为每题再保存一份最终完整快照，并释放驻留状态：

```bash
python3 -B "$REPORT/reproduction/scripts/cross_experience.py" retire \
  --run-root "$RUN" --gpu-url "$GPU_URL"
```

每题退役也先记录意图、只提交一次，成功回执必须为该会话、该版本的 `released`。若中途结果未知，保留现状，先通过 `GET /sessions/<ID>/retire/v1` 只读查询原收据；不要重跑整条命令。结束本次服务前确认没有其他在途任务，并保存远端持久目录。

辅助脚本可先运行以下本地机制测试：

```bash
PYTHONPATH="$RUN/source" python3 -B "$REPORT/reproduction/scripts/test_cross_experience.py" -v
```

测试使用模拟HTTP、模拟Lean进程及小型CPU张量；它们检查拒绝门和文件绑定。上面真正运行的Lean、GPU快照和发布回执构成本次复现证据。

## 同一服务上的更多题目

同一经验可显式给多道新题使用，每题设置新的ID和相同三个固定来源字段。`cpu_runtime.online_batch` 支持在每行清单中记录这三个字段，并让多个CPU搜索同时推进；单个GPU服务内部的模型请求按队列执行。

本篇服务驻留上限为2，来源题尚驻留时只剩一个新题位置。扩大并发前应释放已完成会话或明确增加容量，并按实际显存测量设置上限。[第03篇](03-多题并发.md)给出两个独立GPU服务与两个CPU搜索的复现步骤，保留各自的参数和随机状态。
