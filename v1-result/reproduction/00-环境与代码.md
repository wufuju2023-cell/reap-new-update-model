# 环境与代码准备

## 1. 两边各自负责的工作

**CPU侧**运行Podman、Lean 4.28.0-rc1和Reap，检查证明步骤、维护搜索树、安排任务，并独立复验最终证明。教程命令在Linux或WSL原生目录执行，使用本地Podman上下文。

**GPU侧**运行7B模型服务，提供证明步骤、状态估值和参数训练。本项目成功实验使用AMD宿主的隔离Python环境。两边可以是不同机器；CPU必须能够访问教程中指定的模型服务地址。

基础模型固定为`FrenzyMath/REAL-Prover`，版本`fe76f68d9a88f342cb7b546307c20292fea9cced`，约70亿参数，模型文件约15.25GB。优先复用GPU机器已有权重。本报告不包含权重、CPU/GPU镜像层或大型训练快照。

单服务加载一份7B模型，多题各自有附加参数与训练状态。双服务加载两份7B模型，需要另外预留模型、生成缓存和私有状态的显存。原双服务实验在192GB显存AMD实例上完成。

## 2. 在CPU侧取得可运行代码与原题

可先复制[CPU配置模板](config/cpu.env.example)和[GPU配置模板](config/gpu.env.example)到各自机器的工作区，填写路径与实际镜像ID，再用Bash的`source 配置文件`加载。模板只设置变量，不启动模型、下载文件或执行实验。

| 变量 | 所在机器 | 指向的内容 |
|---|---|---|
| `REPORT` | CPU | 本报告的完整`v1-result`目录 |
| `RUN` | CPU | 新复现实验目录，准备前不能存在 |
| `CPU_IMAGE` | CPU | 本机Podman里实际镜像的完整ID |
| `GPU_URL` | CPU | CPU实际可达的题内模型服务地址 |
| `GPURUN` | GPU | 本次代码、日志、快照与经验的母目录 |
| `MODEL` | GPU | 固定revision的已有7B权重目录 |
| `GPUPY` | GPU | 已检查的AMD Python环境解释器 |
| `DELIVERY_GPU` | GPU | 做集中训练时，GPU侧完整报告目录 |

Python3.12可执行离线准备。下面的`REPORT`指向本报告根目录，`RUN`是你新建的一次复现工作目录；后面的教程继续使用这两个变量。

```bash
export REPORT=/absolute/path/to/v1-result
mkdir -p "$HOME/reap-runs"
export RUN="$HOME/reap-runs/first-reproduction"
python3 -B "$REPORT/reproduction/prepare.py" --output "$RUN"
python3 -B "$REPORT/reproduction/prepare.py" --check --output "$RUN"
```

预期输出为`ok: true`、`source_files: 188`、`input_files: 5`。脚本对照原冻结源码和原实验输入校验字节，再生成新目录；准备失败不会留下一个标为成功的最终目录。

代码目录内的模块说明见[代码导读](code/README.md)。以下检查只运行本地准备工具，不需要PyTorch：

```bash
python3 -B "$REPORT/reproduction/test_prepare.py" -v
```

有PyTorch的环境还可以运行现有框架测试：

```bash
python3 -B "$REPORT/source/current/reproduce.py" local-tests \
  --source-root "$RUN/source"
```

## 3. 准备CPU镜像

先检查本机已有镜像：

```bash
podman info
podman images --no-trunc
```

单题与跨题TTT需要包含`Reap.Training`和`ReapRuntime`的CPU镜像。双服务固定版本采集还需要`Reap.VerifiedCollector`。已有已验收采集镜像可以承担三条流程；没有镜像时，按[CPU镜像三步构建命令](../docker/README.md#从包内源码构建新的cpu采集镜像)从`$RUN/source`构建。

把`CPU_IMAGE`设置为**自己实际检查得到的镜像ID**，新构建的镜像不能填写历史实验的ID：

```bash
export CPU_IMAGE=sha256:REPLACE_WITH_YOUR_LOCAL_IMAGE_ID
podman image inspect "$CPU_IMAGE"
```

构建会下载配方指定的预编译Lean镜像、Reap源码和Mathlib缓存，Lean本体保持4.28.0-rc1。固定基础镜像需有读取权限。各教程显式挂载`$RUN/source`里的Python代码，避免误用旧镜像中预装的控制代码。

## 4. GPU侧目录与Python环境

在GPU机器建立一个母目录，把本次代码、日志、快照和经验放在里面；模型可以继续使用原持久目录。通过你现有的文件传输方式，把CPU侧`$RUN/source`完整复制到`$GPURUN/source`。双服务教程还需要在GPU侧读取本报告及从归档提取的训练数据。

以下变量在**GPU终端**设置：

```bash
export GPURUN=/mnt/workspace/reap-runs/first-reproduction
export MODEL=/existing/models/REAL-Prover-fe76f68d
mkdir -p "$GPURUN"
test -f "$GPURUN/source/gpu_runtime/server.py"
```

先确认平台提供Linux x86_64、Python3.12与可用的AMD PyTorch。PyTorch在AMD上也使用`cuda`接口名：

```bash
python3 -c 'import sys,platform,torch; assert sys.version_info[:2] == (3,12); assert platform.system() == "Linux" and platform.machine() == "x86_64"; print(torch.__version__,torch.version.hip); assert torch.version.hip and torch.cuda.is_available(); print(torch.cuda.get_device_name(0))'
```

已有通过检查的隔离环境可以复用，先设置`export GPUPY=/实际已有环境/bin/python`，跳过下列创建步骤，直接执行其后的依赖检查。需要新环境时，使用宿主PyTorch，在独立虚拟环境中安装源码固定的附加依赖，保留宿主Torch：

```bash
set -euo pipefail
test ! -e "$GPURUN/venv"
python3 -m venv --system-site-packages "$GPURUN/venv"
export GPUPY="$GPURUN/venv/bin/python"
"$GPUPY" -m pip --isolated --require-virtualenv install \
  --no-deps --ignore-installed --require-hashes --prefix "$GPURUN/venv" \
  -r "$GPURUN/source/containers/gpu/requirements-gpu-hashed.lock"
"$GPUPY" -c 'import torch,transformers,peft,accelerate,safetensors; assert torch.cuda.is_available(); print(torch.__version__,torch.version.hip,transformers.__version__,peft.__version__)'
```

新建和复用环境都执行以下检查，用同一个解释器核对GPU可用性和所有固定附加依赖：

```bash
"$GPUPY" -B - "$GPURUN/source/containers/gpu/requirements-gpu-hashed.lock" <<'PY'
import sys
from pathlib import Path
from importlib.metadata import version
import torch
assert sys.version_info[:2] == (3, 12)
assert torch.version.hip and torch.cuda.is_available()
for line in Path(sys.argv[1]).read_text().splitlines():
    if line.strip() and not line.lstrip().startswith('#'):
        name, expected = line.split()[0].split('==')
        assert version(name) == expected, (name, version(name), expected)
print('固定附加依赖与AMD PyTorch检查通过。')
PY
"$GPUPY" -m pip check
```

依赖安装需要网络或预先准备的wheel目录；离线安装可额外传`--no-index --find-links /existing/wheels`。依赖检查失败时先处理环境冲突，保留平台的AMD Torch，不自动安装其他Torch版本。

模型已有可信清单时，使用解压源码中的`containers/gpu/download_model.py --verify-only`核对；该模式读取已有权重并更新核验锁文件，不下载权重。没有清单时先只从官方接口取得固定版本元数据：

```bash
cd "$GPURUN/source"
"$GPUPY" -B -m containers.gpu.download_model \
  --repo FrenzyMath/REAL-Prover \
  --revision fe76f68d9a88f342cb7b546307c20292fea9cced \
  --manifest-only --save-manifest "$GPURUN/model-manifest.json"
```

**GPU机器已经有权重：** 只检查现有文件。缺文件或哈希不符会失败，不会自动下载。

```bash
cd "$GPURUN/source"
"$GPUPY" -B -m containers.gpu.download_model \
  --repo FrenzyMath/REAL-Prover \
  --revision fe76f68d9a88f342cb7b546307c20292fea9cced \
  --manifest "$GPURUN/model-manifest.json" --verify-only --output "$MODEL"
```

**GPU机器第一次准备权重：** 将`MODEL`设置为GPU持久磁盘上的新目录，预留模型及训练快照空间，再执行下载。下面实际下载约15.25GB到GPU机器，不在CPU电脑执行：

```bash
cd "$GPURUN/source"
"$GPUPY" -B -m containers.gpu.download_model \
  --repo FrenzyMath/REAL-Prover \
  --revision fe76f68d9a88f342cb7b546307c20292fea9cced \
  --manifest "$GPURUN/model-manifest.json" --output "$MODEL"
```

下载工具按官方清单校验文件、分片索引和模型结构，成功后生成核验锁文件。模型公开可读；网络或平台访问失败时保留具体错误，先处理环境，不更换模型revision。下载完成后，后续实验使用这个目录。

新建服务分别使用`$GPURUN/snapshots`保存题内快照、`$GPURUN/experiences`保存跨题参数经验。集中训练的发布仓库在第三篇中单独准备；这几类目录不能互相替代。

## 5. CPU访问GPU服务

模型服务绑定GPU机器的`127.0.0.1`，仅供可信连接使用。教程中的`GPU_URL`始终是**CPU所在Linux系统能够访问的地址**；不同机器的`127.0.0.1`各自指向本机。

两边同一机器时，可直接使用`http://127.0.0.1:8760`。具备正常SSH入口时，可在CPU机器用SSH端口转发：

```bash
ssh -N -L 18760:127.0.0.1:8760 USER@GPU_HOST
```

保持该终端运行，在另一个CPU终端设置`export GPU_URL=http://127.0.0.1:18760`。双服务流程分别转发8761和8762。该方法要求平台实际提供SSH；ModelScope页面登录不等于具备SSH入口。

原实验通过Edge的OpenCLI桥访问ModelScope。解压源码里的`tools/amd_jupyter/http_bridge.py`提供该入口，需要填写当前浏览器配置、当前实例ID、远端Python、`remote_http_job.py`路径、独立任务落盘目录，以及允许访问的全部session ID。运行`python3 -B -m tools.amd_jupyter.http_bridge --help`可查看准确参数。此桥为每个模型服务指定`--target-port`，双服务分别使用8761、8762；默认只允许明确列入`--session-id`的任务。应在题目编号确定后配置，不能套用旧实例或旧会话编号。

当前两台机器的路径和访问权限由部署环境决定，复制报告不会恢复历史浏览器登录。任选一种已经建立的可信通道即可；三篇教程的模型接口相同。服务启动后，在CPU侧检查：

```bash
curl --fail --silent --show-error "$GPU_URL/health"
```

只有实际返回对应服务信息后才启动搜索。CPU容器使用本机网络访问该地址；证明复验另开断网容器。

## 6. 新实验的文件边界

每次使用新的session ID、CPU输出目录、GPU快照目录和发布编号。已有来源经验只读复用，输出目录保持独立。不要把报告里的历史成功收据放进新实验当作本次验收。

先继续[单题TTT](01-单题TTT.md)，或直接按[多题并发](03-多题并发.md)准备集中训练参数和双服务。每条流程结束后按[结果检查](04-结果检查与故障处理.md)保存证明、回执、版本和实际退出状态。
