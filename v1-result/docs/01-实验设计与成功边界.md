# 实验设计与成功边界

## 研究目标

在证明搜索尚未结束时，使用Lean产生的真实搜索信息更新模型，让同一树的后续生成使用新版本，最终取得可复验的Lean证明。**最新主例01r1完成三次更新，原树后续依次使用v1、v2、v3，最后证明成功；通信、训练前后快照和独立无网络Lean复核均通过。**05r2也完成两次更新后证明。五题详情见[09](09-五题尝试与并发结果.md)；历史E的一次更新结果仍保留在[03](03-实际TTT结果与证据.md)。

简单说：模型提出证明步骤，Lean真正尝试；搜索积累的数据用来调整模型，随后继续解同一道题。下面保留技术定义；不熟悉术语时先读[10-原设计逐项对照与实际流程](10-原设计逐项对照与实际流程.md)。

## 系统分工

| 部分 | 工作 |
|---|---|
| A CPU | 运行预编译Lean与固定Reap/Mathlib；搜索并验证候选步骤、记录过程、安排多题 |
| B GPU运行时 | 用REAL-Prover 7B提出步骤、估算状态价值，更新LoRA和价值头；各题状态独立并可保存快照。本次真实运行于远端AMD宿主 |
| 通信 | 历史实验经Edge/OpenCLI把本地请求传到远端，保存原始请求/响应以核对确实用了哪个模型版本 |
| 最终B镜像 | 烘焙固定7B和GPU代码；构建材料已准备，实际GPU容器验收仍待完成 |

CPU可以并行搜索多个session；GPU的单actor串行处理请求。base共享且冻结，每个session拥有独立LoRA、value、optimizer、RNG、buffer、版本和快照。

### 题内隔离与题间继承

上述隔离约束针对**当前同时解题的可变训练状态**，防止一题的更新直接改变另一题。共享冻结base不禁止题间继承：后续可以在明确版本边界，把上一题已确认的LoRA/value初始化给新题，再独立训练；这需要另行设计和验收。

**当前新session独立初始化**，尚未继承上一题的LoRA或价值头。原文第9篇讨论的跨题经验继承按用户要求延期，当前保留题内训练状态隔离。

## 数学与在线时序

保留Reap的PUCT、OR/AND和验证核心，增加训练观察与checkpoint。实际执行的strict profile为`online-search-visit-backup-v1`：

```text
π_target(a|s) = N(s,a) / ΣN(s,b)
L_policy = −Σ π_target(a|s) × Σtoken log pθ(token | prompt, prefix)
d = 1 + log(max(V, 1e−6)) / log(γ)
b = node.valueSum / node.numVisit
G = max(1e−6, γ^(−b−1))
L_value = (V − G)²
```

γ必须来自实际Lean配置并与B一致，本次0.99。policy学习canonical tactic的联合token概率，不做长度平均、不补隐式EOS；正则使用冻结base的prefix KL。value与Reap距离转换保留一步偏移。由于core先平均距离再指数，该目标有明确近似，不能称完整TD/MC期望的严格等价实现。

数学reward仅0/1。E学习时未终局，reward=0，但有效backup提供非零value目标。未访问节点、零计数和sentinel不伪造训练样本。E只有一个有效训练候选，因此`π=[1]`。

每个checkpoint先暂停Lean，再提交至多一个更新；回执确认版本后ACK，原树继续。默认单题最多5次更新，没有TTT总deadline；五分钟是期望，单次HTTP/屏障保护超时另行保留。PPO/GRPO、长训练和V2不属于本次必需项目。

## 验证结果与后续工作

1. 搜索证据：原题、树、访问、backup、prompt和动作来源对应。
2. 学习证据：线上回执、真实前后张量与optimizer状态相符。
3. 在线消费：后续policy/value HTTP实际使用新版本，树事件连续。
4. 最终验证：保存proof，在无网络CPU容器重验原命题。
5. 交付验证：A/B镜像构建、B在合法AMD容器运行与发布分别验收。

01r1与05r2已完成前四项：分别三次/两次更新后证明，真实调用与训练前后快照、独立Lean复核对应。中间更新用连续回执/参数指纹连接，未对每个中间版本另存快照逐张量复算；本轮未重复完整7B主体哈希或现场restore。历史E一次更新后证明、F五次更新后未证仍各自保留。
