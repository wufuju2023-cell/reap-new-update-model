# 实验结果：TTT框架已跑通的流程

这些实验分别检查题内学习、跨题继承、集中训练、恢复和并行运行。每节给出要解决的问题、实际执行过程和结果；原始文件放在对应的证据目录中。

可以从你关心的流程直接读起：[未解完就训练](#same-tree-three-updates)、[新题继承已有经验](#cross-problem-inheritance)、[新证明用于下一轮训练](#proof-training-loop)、[两种来源的证明一起训练](#mixed-proof-training)、[多题同时搜索](#parallel-lean-search)、[中断后恢复](#published-version-recovery)。

## 1. 连续训练三次，再接着原来的搜索完成证明

**题目。** 一个数列从1开始，每次加2；另一个数列从0开始，依次累加前一个数列。要求同时证明：第一个数列的第n项为`2n+1`，第二个数列的第n项为`n²`。模型得到命题和递推条件，没有得到参考证明。实验文件中的题名是`CoupledOddSquare`。

**过程。** 7B模型提出证明步骤，Lean检查，Reap继续搜索。搜索第8步时仍未找到完整证明，程序用已有搜索反馈做第一次训练；第9步使用更新后的模型继续搜索，再做第二次训练；第10步使用第二次更新后的模型，再训练一次；第11步使用第三次更新后的模型，找到完整证明。整个过程保留了同一个Lean进程和同一棵搜索树。

第一次训练时，整题成功奖励仍为0。策略部分学习已探索过的`intro n`，即“引入变量n”；价值部分学习搜索汇总的估值，目标约为0.526。训练信号来自搜索访问次数和状态估计，详细原理见[题内学习的训练目标](01-题内在线TTT.md)。

**结果。** 三次模型更新均有实际请求、执行回执和参数变化记录；每次更新后的参数都参与了后续搜索。最终证明在独立的断网Lean环境中复验通过，没有使用跳过证明的占位公理。搜索及中间训练的计时约123秒，不含环境准备、首末状态保存和独立复验。

这次实验验证了“搜索反馈训练模型 → 确认更新 → 原搜索继续 → 导出并检查证明”的题内循环。对应运行编号为`multi-20260827-01r1`，可查[三次更新与生成请求的核对记录](../../evidence/multiround/wire-01r1.json)、[训练前后状态及训练目标](../../evidence/multiround/snapshot-audit.json)和[五题原始材料说明](../../evidence/multiround/README.md)。

<a id="same-tree-other-proofs"></a>

同一组五题实验中，**带系数的三角数累加题经过1次更新后证明，立方和累加题经过2次更新后证明**，两份证明也通过独立Lean检查。另外两题在预算内没有完成证明，失败和重试均保留在[五题结果记录](../../evidence/multiround/summary.json)中。下一节记录的是另一次跨题继承实验，使用各自那次运行的训练次数。

## 2. 三道新题继承同一份经验，再各自学习和证明

**目标。** 把一道题训练得到的模型参数交给其他题作为起点，同时保持各题的搜索和训练独立。

**过程。** 先把一份已经通过验收的训练参数保存为只读经验。三个新任务分别复制这份参数，重新建立自己的搜索树、训练进度和临时数据，再运行题内TTT。

| 题目 | 要证明的内容 | 本次训练次数与结果 |
|---|---|---|
| 立方和累加 | `1³+…+n³`等于`[n(n+1)/2]²`；实际命题用乘4的形式避免整数除法 | 更新4次后证明；[生成的证明](../../evidence/current/cross-problem/files/proof-check-experience-target-05/05-CubeAccumulatorProof.lean) |
| 带系数的三角数累加 | 从a开始，每次加`b(n+1)`，得到`2f(n)=2a+bn(n+1)` | 更新1次后证明；[生成的证明](../../evidence/current/cross-problem/files/proof-check-inherit-concurrent-03/03-ScaledTriangularProof.lean) |
| 等差数列及其累加 | f从a开始、每次加b；g从0开始、每次加当前f。证明`f(n)=a+bn`及`2g(n)+bn=2an+bn²` | 更新1次后证明；[完整命题与生成的证明](../../evidence/current/cross-problem/files/proof-check-inherit-refill-02/02-AffineAccumulatorProof.lean) |

**结果。** 三题起始参数逐项匹配同一份来源经验；各题后续训练相互隔离，来源文件未被改写。三份最终证明都通过独立Lean检查。

同时最多运行两个搜索任务，前两个任务的搜索记录有约40秒重叠，其中一个完成并释放资源后，第三个任务补入。这组实验的模型请求由同一个GPU服务依次处理；[第9节](#parallel-lean-search)另行验证两个模型服务同时支持搜索。

这次实验跑通了“继承经验 → 多题独立学习 → 完成后保存与释放 → 处理下一题”。详见[三题实验说明](../../evidence/current/cross-problem/README.md)、[参数来源与隔离检查](../../evidence/current/cross-problem/files/snapshot-audit.json)、[并发和补位记录](../../evidence/current/cross-problem/files/concurrency-audit-v2.json)。

## 3. 新模型解出一道题，新证明再用于下一次训练

**题目。** 已知数列从2开始、每次加3，证明`f(n)=2+3n`。实验中的名称为`AffineStrideThree`。

**过程。** 集中训练程序先保存第一轮训练结果，并发布可供新题使用的参数。新题复制该版本，整次搜索保持参数固定，寻找证明。证明完成后，另一个Lean环境检查完整证明，并逐步重放，记录“当前证明状态—下一步证明动作”。本题得到两条这样的训练记录；它们进入下一次训练，训练程序随后保存并发布第二版参数。

**结果。** 新题搜索约66秒，完整证明检查及逐步重放合计约54秒。第二次训练确实读取了新证明数据；另一个新任务初始化后，参数与第二版发布结果一致。这次第二版只检查了初始化，没有继续解另一道题。

这验证了一轮“训练出新版本 → 用它解题 → 检查新证明 → 用新证明继续训练”的反馈循环。证明本身见[模型生成的完整证明](../../evidence/current/central-learner/README.md#generated-proof)，执行和参数检查见[实验说明](../../evidence/current/central-learner/README.md)及[原始报告](../../evidence/current/central-learner/files/report.json)。

运行期间曾遇到共享目录写入、参数发布和验证材料安装问题。恢复从已经保存的第一次训练结果继续，没有重复训练；证明检查通过后，同一份材料改在本机目录完成安装。原失败及处理经过保留在上述证据中。

## 4. 把模型生成的证明与数学库原有证明一起训练

**材料来源。** 第一类是模型生成、经Lean独立验证的4份证明：第1节五题实验中的三份成功证明，以及第3节新解出的等差数列证明，共整理出13条步骤记录。第二类来自固定版本数学库Mathlib的`Logic/ExistsUnique.lean`文件，取其中3份已有证明，共7条步骤记录；内容涉及“存在且唯一”的数学性质。Codex负责编写采集与核查脚本，训练使用的这些证明步骤保留了数学库原文。

**训练方法。** 一条记录包含某个证明状态和下一步动作。每批取9条模型生成的步骤记录，再取1条数学库原有的步骤记录，共10条，每条对训练目标的权重相同。采样数量按步骤记录计算。策略网络学习下一步动作，价值网络学习根据已验证证明步骤数构造的目标。

**实际过程。** 完成第一批训练后，保存模型参数和完整训练状态，发布第一版可复用参数。随后销毁训练器并重新创建，从保存位置恢复，再执行第二批训练、发布第二版。恢复内容包括模型参数、优化器进度、随机状态和两类材料的读取位置。

**结果。** 两批都发生了真实7B训练，可训练参数均有变化；恢复前后的状态逐项一致。两批合计使用了13条不同的模型生成步骤和2条不同的数学库步骤。两个新任务分别取得对应版本的参数，旧任务保留原参数，基础模型参数前后保持一致。两次“训练并保存状态”分别约24秒，发布与恢复另计。

这次实验验证了两类已验证材料按固定比例参与训练、训练状态完整恢复，以及新旧版本互不覆盖。详见[两类材料与混合训练说明](../../evidence/current/mixed-learner/README.md)和[原始训练报告](../../evidence/current/mixed-learner/files/report.json)。原始数学库文件、证明片段与采集记录也保存在该阶段材料中。

## 5. 分别证明一个真命题、推翻一个假命题

**输入。** 使用上一节训练得到的第二版参数，处理两个独立任务：证明“每个自然数都等于自身”；反证“所有自然数都等于0”，也就是证明这句话的完整否定。输入包含命题，不提供证明。每题最多搜索8步。

**过程。** 两题都固定使用选定参数，搜索期间不训练。搜索结束后先保存结果，确认释放该题的模型状态；随后独立Lean环境检查完整证明及其公理依赖，再重放每一步并保存训练材料。

**结果。** 最终一次运行中，两题都通过独立检查，分别形成1条、2条模型生成步骤记录。整批约82秒。它们的搜索回调可并发安排，但本次实际搜索记录没有重叠。

这之前有两次尝试：一次在CPU仓库访问预检时退出，尚未创建GPU任务；另一次因提示只显示未展开的定义名称，两题均耗尽预算。最终运行把原定义展开给模型，保持原命题及最终证明类型不变。后两批共4个任务均保存结果并释放资源。

这验证了固定版本的证明和反证、完整证明检查、步骤材料收集与任务回收。详见[成功运行说明](../../evidence/current/collector-r3/README.md)、[原始批次报告](../../evidence/current/collector-r3/files/collected/host/campaign-report.json)和[此前耗尽预算的记录](../../evidence/current/collector-r2/README.md)。

## 6. 继承已有训练成果，恢复后加入新证明继续学习

**输入。** 新训练器从第4节的第二版参数开始，建立自己的训练进度和数据读取位置。最初仍使用13条模型生成步骤和7条数学库原有步骤。

**过程。** 先训练一次、保存并发布参数，再销毁和恢复训练器。然后加入第5节反证成功产生的两条步骤记录，执行第二次训练。每批仍取9条模型生成步骤和1条数学库原有步骤，数据读取从保存的位置继续。

**结果。** 第二次训练实际取到了新增的两条步骤。两次训练均改变了可训练参数，恢复状态完全一致，原经验来源和先前创建的任务都没有被新训练改写。两次“训练并保存状态”分别约55秒、77秒。

这验证了“已有模型经验 → 新训练任务 → 保存和恢复 → 加入新证明 → 继续训练”的流程。本次新增证明来自第5节；这里检查训练和参数传递，没有再用本次训练的新版本解题。详见[继续学习实验说明](../../evidence/current/continual-mixed/README.md)、[原始报告](../../evidence/current/continual-mixed/files/collected-final/result/report.json)和[保存的继续点](../../evidence/current/continual-mixed/files/collected-final/result/final-continuation.json)。

## 7. 搜索更新与运行保护

- **训练后重新评价部分搜索状态。** 一次模型更新后，重新计算两个尚未解决的搜索状态的估值，后续搜索使用新版本并完成证明。历史访问次数和原训练统计保留。见[重新估值的实际记录](../../evidence/current/selection-refresh/README.md)。
- **更新变化过大时退回原状态。** 测量训练后模型与基础模型的输出差异，分别测试允许更新和拒绝更新；拒绝时，模型及训练状态完整恢复。见[更新保护与回滚](../../evidence/current/kl-guard/README.md)。
- **用成功证明同时训练生成和评价。** 使用11条已验证证明步骤做一次真实联合训练，检查参数变化、基础参数保持、任务隔离和恢复。见[成功证明训练记录](../../evidence/current/verified-replay/README.md)。
- **结束任务时复用已经保存的状态。** 回收模型任务时复用已保存参数，避免重复导出；实际释放约254MB已分配显存。见[状态复用和资源回收](../../evidence/current/snapshot-reuse/README.md)。

<a id="parallel-inference"></a>

## 8. 两个模型服务同时处理固定请求

**输入与过程。** 在同一张AMD显卡上加载两个独立7B模型服务。给它们同一组固定的证明状态，先依次调用，再同时调用；两种方式分别生成候选步骤并计算估值，重复三轮。

**结果。** 各服务在依次调用和同时调用时，输出的证明步骤、生成分数、估值及私有状态一致。三轮计时的中位结果表明，同时调用的速度约为依次调用的1.93倍。

这说明同卡双服务能同时处理模型请求。该实验不包含Lean搜索或训练；完整解题速度另行测量。见[输入、逐轮输出和计时](../../evidence/current/inference-replicas/README.md)。

## 9. 两个模型服务分别支持一道题的真实搜索

**输入。** 沿用第5节的两个命题，分别分配给两个独立7B服务。两题使用相同的已发布参数，各自最多搜索8步，搜索期间不训练。

**过程。** 每道题固定连接自己的模型服务。CPU运行独立的Lean搜索树，向对应服务请求候选步骤和估值。搜索结束后先保存结果、释放该模型任务，再独立检查完整证明及每一步操作。

**结果。** 真命题的证明和假命题的反证都通过独立检查，分别得到1条、2条证明步骤记录。整批约75秒，两题搜索记录的时间区间重叠约7秒。任务结束后，两个模型服务和协调程序均正常退出，10次原始模型服务请求全部成功。

这次实验把双服务并行接入了实际解题流程。约7秒指搜索记录的重叠，其中包含CPU处理和通信等待；本次没有测量相对单服务的完整解题加速比。详见[双服务搜索、证明及独立审核](../../evidence/current/replica-collector/README.md)。

## 10. 新任务取得新版本，服务中断后从已保存状态恢复

**要检查的流程。** 训练程序保存并发布新参数后，新任务取得最新确认的版本；已经开始的旧任务保留原版本。

**原运行。** 第一轮训练完成后保存第一版参数，第一个模型服务用它完成生成和估值。第二轮训练完成后保存第二版参数，新任务的预约记录也绑定了第二版。此时另行保存旧任务的完整模型状态，与第二轮训练前一致。

随后，一个服务因900秒控制等待超时退出，新任务连接失败，原运行以失败结束。已经完成的两次训练和两版参数均保留。

**恢复运行。** 新建两个模型服务：第一个从原快照恢复旧任务的完整模型状态；第二个加载已保存的第二版参数，实际执行生成和估值。没有重新训练或重新发布。恢复后的旧任务状态在新版本运行期间保持不变；两个服务及协调程序正常退出，8项检查全部通过。

这组分阶段实验验证了新版本发布、任务选版、旧状态恢复和新参数实际使用。它没有运行新的Lean搜索，原失败记录单独保留。详见[原运行及失败位置](../../evidence/current/latest-release-gpu/README.md)和[恢复通过的结果](../../evidence/current/latest-recovery-gpu/README.md)。

## 计时范围与后续工作

本页记录的是不同阶段的实际运行。题目相同但运行不同，训练次数和耗时也分别记录；各阶段使用当时保存的代码版本，原始材料中可核对。

题内搜索计时不含环境准备、模型加载、首末状态保存和独立证明检查。集中训练的计时注明是否包含状态保存。并发区间包含CPU和通信等待，不能用它代替显卡计算时间。

这些实验验证了上述流程和有限批次的运行稳定性。本轮没有追加成功率效果对照；长期运行、目标变体课程及其他待完成能力见[后续工作](06-待办与验收范围.md)。本轮结束后已保存继续点并停止AMD，见[停止回执](../../evidence/current/latest-recovery-gpu/files/collected/stop-receipt.json)。
