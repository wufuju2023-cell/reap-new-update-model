# 跨题经验继承与中央训练

## 新题的参数来源与独立状态

跨题经验可以保存为一个不可改写的参数版本。新题明确选择这个版本，复制获准的小规模附加参数和价值头；来源记录一并保留，方便逐项核对。

新题的优化器进度、随机数状态、训练缓存、操作记录和搜索树重新建立，本题更新次数仍从零开始。原来源和同期运行的其他题保持不变。真实三题继承实验已核对参数确实传入，随后三题各自训练并证明，见[跨题继承实例](04-实际实例与验收结果.md#cross-problem-inheritance)。

选择来源时有三种规则：从固定基础模型重新开始（fresh）；引用一个明确的前序经验（chain）；从获准集合中按题族、标签、优先级和稳定顺序选取（bank）。没有匹配项时默认报错，只有显式允许才回到基础模型。这些规则已有本地验收；底层参数继承另有真实7B证据，本轮没有为新选择规则再跑GPU，也没有语义相似题检索。见[来源选择原始记录](../../evidence/current/experience-policy-local/README.md)。

## 从一次搜索到下一次中央训练

中央训练路线把“搜索”和“更新共享经验”分开。搜索端使用一个固定发布版本完成整次尝试，期间不做本题训练。中央训练程序只从独立验收通过的数据学习，再发布供后续搜索使用的版本。

实际顺序是：

1. 为题目选择发布版本，创建私有模型状态，开始Lean和Reap搜索。
2. 搜索结束后保存结果，确认释放该题占用的模型状态。
3. 有完整证明或反证候选时，在独立断网环境检查整条证明及公理，再逐步重放每个“当前状态→下一步”。
4. 通过检查后生成不可变数据包，并明确加入下一次训练的数据目录；失败或预算耗尽的结果留档，不作为成功记录。
5. 中央程序取固定批次训练，保存完整继续点，然后发布新参数。

独立验证使用已经保存的材料，不需要继续占用该题的GPU状态，可以与其他题的搜索并行。已有一次真实实验完成“发布R1→新题证明→独立验收→回流训练→发布R2”，见[证明回流训练实例](04-实际实例与验收结果.md#proof-training-loop)。

## 训练记录与数据来源

每条训练记录由**一个证明状态和该状态下的下一步证明动作**组成。生成的数据来自模型生成并经Lean验证的证明步骤；另一类来自数学库原有证明。

混合训练每批取**9条模型生成并经Lean验证的证明步骤，加1条数学库原有证明步骤**，共10条记录，每条权重为0.1。这里的9和1是步骤记录数量，不是9道题和1道题。同一份证明可以贡献多条记录，固定采样规则也允许重复取到同一条。

生成证明的数据包保留实际命题、模型输入、步骤、使用的版本、完整证明和独立检查结果，共17个文件。数学库来源的数据包保留固定源码提交、原文件与声明、证明字节位置、实际状态采集和独立重放结果，共22个文件。读取时只接受数据包指纹和行号，不能让调用方自行填入训练目标或把其他数据标成成功证明。

本轮数学库来源固定在提交5352afccd6866369be9de43f5b7ec47203555f44，选取Mathlib/Logic/ExistsUnique.lean中的elim₂、intro₂和unique₂，共3、2、2条步骤。采集和检查程序由本项目编写，包装中的辅助证明不计入训练动作。当前入口只支持这类限定的线性证明，见[数学库来源与原始数据](../../evidence/current/mixed-learner/README.md)。

## 生成目标与价值目标

策略部分学习在记录中的状态下生成那个已验证步骤，并包含约定的一次结束标记。价值头只读取动作之前的状态，预测这条成功证明还需要多少步的类别。

步数标签来自实际验证过的证明：一个生成的完整策略字符串计一个动作，仅切换子目标的操作不计；如果证明分成多个子目标，就按最长分支计算剩余动作数，并取负值作为标签。数学库的线性证明则按剩余动作数计算。当前混合训练同时训练两类来源的策略和价值，这是本项目选定的训练方式。

这与[题内训练](01-题内在线TTT.md)不同：题内价值头拟合搜索估计转换出的折扣数值；这里的价值头预测已验证证明的步数类别。两者使用不同训练目标和兼容规则，不能直接互相导入。本轮混合训练的类别范围为剩余1到8步，超出就拒绝；其他成功证明训练配置按各自范围检查。

## 已完成的三个训练阶段

**只使用生成并验证的证明步骤。** 这一阶段验证了成功步骤的联合训练，以及新证明回流后继续训练和发布。它有自己的价值类别定义，原始依据见[成功证明训练](../../evidence/current/verified-replay/README.md)和[中央回流实验](../../evidence/current/central-learner/README.md)。

**从基础模型开始混合训练。** 固定两类数据目录，每批按上述9条加1条训练。真实运行完成两次更新，中间保存、删除并完整恢复训练状态，再发布两个参数版本；新版本没有污染旧搜索端。见[混合训练实例](04-实际实例与验收结果.md#mixed-proof-training)及[原始证据](../../evidence/current/mixed-learner/README.md)。

**从已发布经验继续学习。** 新训练任务复制一个兼容的旧版本，建立自己的优化器等状态。原有生成证明目录顺序保留，可在末尾追加新的已验数据；数学库目录和随机种子固定，两类数据的采样位置分别累计。真实运行完成第一次更新、完整恢复、追加新数据、第二次实际取样和发布。旧运行保持只读，见[持续学习实例](04-实际实例与验收结果.md#continued-learning)及[原始证据](../../evidence/current/continual-mixed/README.md)。

这三个阶段是独立实验，不能把它们的时间、证明数量或版本编号拼成一次运行。两批混合训练也不代表已经遍历所有数学库记录。

## 保存继续点、发布新版本和处理失败

完整检查点用来精确继续原训练，包含参数、优化器、随机数状态、版本、采样位置和操作记录。发布版本只包含新搜索端可以复制的获准参数及来源。发布之前必须先成功提交对应检查点；文件出现或优化器运行结束，都不能代替完整提交确认。

如果训练已提交而发布失败，就查明原发布结果，不重新训练。若训练结果或磁盘提交结果未知，保存原操作身份并停止相关后续操作，直到原结果确定。内存可能已改变，不能把所有磁盘错误都描述成自动回滚。

默认调用明确指定发布版本。可选的最新版本模式会在新任务预约时固定最新已确认版本，已有任务保持原版。最新真实验收先完成两次训练、发布和预约，随后子服务超时导致原运行失败；独立恢复原R1、使用已确认R2实际推理通过，恢复没有新增训练或发布。完整过程见[发布与恢复实例](04-实际实例与验收结果.md#published-version-recovery)、[原失败](../../evidence/current/latest-release-gpu/README.md)和[恢复证据](../../evidence/current/latest-recovery-gpu/README.md)。

通用模型可以汇总不同题的合格证明。专门针对某个目标训练时，目标和变体来源需要另外验收；目前用途字段只说明计划用途，不能证明数据都属于该课程。目标变体课程仍暂停。
