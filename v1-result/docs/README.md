# 报告导航：先看成功过程，再复核或重跑

**第 1 题经过三次真实 GPU 更新后证明成功，第 5 题经过两次更新后证明成功。** 两题的每个新版本均用于后续搜索，最终证明已在断网 CPU 容器中重新检查通过。此次验证的是当前题目的 TTT 流程；跨题经验继承和 GPU 容器验收仍未完成。

## 按流程看这次实验

| 顺序 | 做了什么 | 主要看哪些文件 |
|---|---|---|
| 1. 准备 | CPU 容器提供 Lean/Reap；远端加载固定的 REAL-Prover 7B | [02 运行准备](02-运行流程与复现.md)、[source](../source/README.md)、[08 CPU镜像验收](08-CPU交付镜像验收.md) |
| 2. 搜索 | GPU 给出候选证明步骤，CPU 上的 Lean 检查，Reap 保存搜索记录 | [10 实际流程](10-原设计逐项对照与实际流程.md)、新证据包里的题目与 `observer.jsonl` |
| 3. 训练 | 用真实搜索反馈更新 LoRA 和价值头，得到新版本 | [09 第1题逐轮记录](09-五题尝试与并发结果.md)、`checkpoints/` 学习请求与回执 |
| 4. 继续 | 收到更新回执后，原搜索树继续使用新版本 | [10 设计对照](10-原设计逐项对照与实际流程.md)、`evidence/multiround/wire-01r1.json` |
| 5. 验收 | 读取实际参数快照；重新编译生成的证明，确认 Lean 通过 | [09 核验结果](09-五题尝试与并发结果.md)、[evidence](../evidence/README.md) |
| 6. 复现或交付 | 解出源码与题目，创建新 session 重跑；有权限的环境再验 GPU 容器 | [04 独立复现prompt](04-新agent复现prompt.md)、[docker](../docker/README.md)、[06 容器边界](06-容器未完成原因与交付边界.md) |

学习参数发生变化、更新后的模型参与搜索、最终证明成立，这三件事分别有证据。它们不自动证明训练提高了解题速度或成功率；需要另做不训练的对照实验。
