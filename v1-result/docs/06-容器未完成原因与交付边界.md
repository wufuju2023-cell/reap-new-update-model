# Docker / Podman 为什么失败，接下来怎么部署

## 先看结论

**本地 CPU 镜像 A 已经成功构建并运行。未完成的是远端 AMD 的 GPU 容器 B：当时实例限制了二级容器所需的操作，而且后续检查没有找到可用的 Docker 服务。**

因此，本次 TTT 使用“本地 CPU 容器 + 远端 AMD 宿主 Python 环境”完成。第1题三次更新、第5题两次更新后均证明成功；GPU容器的交付工作仍需继续。见[五题结果](09-五题尝试与并发结果.md)。

## 1. 远端容器启动失败在哪里

平台提供的开发环境本身有隔离限制。在里面再启动 Docker/Podman 容器，还需要平台支持相应的容器服务和挂载操作。

| 检查阶段 | 实际报错或观察 | 对本次运行的影响 |
|---|---|---|
| 较早一次实例，安装Podman后尝试启动容器 | `/proc/sys/net/ipv4/ping_group_range` 只读 | 容器运行时需要操作的内核配置受限 |
| 同次启动尝试 | `mount proc ... Operation not permitted`，退出码126 | 建立容器文件系统所需的挂载被拒绝，容器未正常启动 |
| 后续一次实例，检查Docker服务 | `Cannot connect to the Docker daemon at unix:///var/run/docker.sock` | 虽有Docker命令行，但没有连接到可工作的Docker服务 |
| 同次后续检查 | 三个候选socket均不存在，含 `/var/docker/proxy/docker-proxy.sock`；`CAP_SYS_ADMIN=false`，Podman未安装 | 当次环境没有发现可用的容器服务入口；UID为0也未提供所需的全部能力 |

这些是**不同实例、不同时间的检查**。后续检查没有重新启动容器，具体字段保存在[环境检查记录](../evidence/current-container-access.json)。较早实例安装过Podman，不代表后来实例也装好了。

失败发生在容器基础环境检查或启动阶段。单独安装Docker/Podman命令行、再次编译Lean或下载模型，都不能补上缺失的平台服务与权限。B的完整构建和容器内GPU运行尚未验收，其依赖兼容性也仍需测试。

## 2. 本地 CPU 镜像现在是什么状态

本地A已有成功产物及运行证据：原GPU实验使用 `df23cd6…`，新交付镜像为 `623ae445…`。新镜像的源码检查、实际用户、无网络双session测试和原证明重新编译均通过，详见[08-CPU镜像验收](08-CPU交付镜像验收.md)。

新A构建的外层命令曾报 `exit: : numeric argument required`，原因是包装脚本变量转义出错，原Podman退出码没有被正确保存。构建日志中的提交/标记、实际镜像ID及后续容器运行已经核验成功；报告保留“原退出码未知”这一事实。这与远端GPU容器的权限失败是两件事。

## 3. 为什么其他环境可以用 Docker

有Docker服务并允许所需设备、挂载操作的主机，可以按正常流程构建和运行镜像。不同开发平台、资源组及实例配置，提供的权限不同。

阿里云DSW官方支持二级容器，但限定资源组，并要求创建实例时开启DinD。如果官方代理socket存在，可按文档配置 `DOCKER_HOST`；当次检查中该socket不存在。官方还限制提权、host IPC等参数，设备与目录挂载须符合平台要求。[DSW官方说明](https://help.aliyun.com/zh/pai/using-docker-in-dsw)

这份官方说明不保证当前ModelScope AMD实例具备相同功能；是否能开通，需要平台或管理员确认。参考仓库提供Dockerfile和构建入口，也需要在对应运行环境完成实际测试。

## 4. 后续部署办法

1. **先确认运行环境。** 使用具备Docker/Podman服务和AMD设备权限的获授权主机；或者请平台确认能否开通官方二级容器功能。无需尝试绕过平台限制。
2. **构建GPU镜像B。** 按[docker目录说明](../docker/README.md)，在远端使用已验证的7B模型准备构建目录，再构建镜像。构建本身不需要GPU，模型权重不下载到本机。
3. **在AMD GPU上验证B。** 检查ROCm/PyTorch、模型加载、实际训练、session隔离与恢复，再连接A运行Lean TTT。宿主环境的Torch2.11与候选B的Torch2.10需分别验证兼容性。
4. **验证通过后发布镜像。** 镜像仓库、访问权限和模型许可需要确认。本次上传GitHub的是报告、源码和Docker构建材料，不包含已发布的GPU镜像。

**当前缺项：GPU镜像B的实际构建、容器内GPU验收及镜像发布。** CPU容器与已完成的题内多轮TTT结果保持有效。
