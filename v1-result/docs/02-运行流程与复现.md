## 已走通的准备顺序

1. **CPU环境。** 本机WSL/Podman准备A，复用预编译Lean，编译固定Reap及hooks；核题目、依赖和镜像身份。不要从源码重编Lean本体。
2. **浏览器与实例。** 用户在Edge登录ModelScope、完成验证码并启动AMD；agent检查OpenCLI Browser Bridge连接与当前实例身份。实例开关始终由用户负责，不使用内置浏览器控制。
3. **远端模型。** 检查持久目录中的固定revision和官方manifest；有文件时先验证，不重下15GB。已用路径为`/mnt/workspace/models/REAL-Prover-fe76f68d`，重接管后确认路径和内容。缺失时按源码中的官方清单下载/校验工具准备，权重始终留远端。
4. **GPU环境。** 隔离venv复用宿主ROCm Torch，只装锁定辅助库；核HIP、GPU和库版本，不能替换宿主Torch。先做GPU数值/隔离预检，再启用`real-search --gamma 0.99`服务。
5. **桥接。** 根据本次浏览器profile、实例、远端Python/helper路径配置`tools/amd_jupyter/http_bridge.py`；session白名单只含本轮新名称。先核现有服务与端口，避免重复启动或干扰其他实验。

每一步缺少权限、模型、访问或必要输入时停下反馈。当前B容器权限问题见[06](06-容器未完成原因与交付边界.md)，不影响在既有授权宿主环境复现实验。

## 历史 E/F 示例入口

为run、session、容器、输出卷和远端snapshot/job目录生成全新名称。历史E/F名称用于查证，不能重用。将`docker/batch.example.jsonl`复制为新manifest，替换session并选择题目；若只复现E，可只保留`RecurrenceSquare.lean`一条。每个名称须同时加入bridge白名单。

在包根目录、WSL/Linux中，确认`GET /health`为`backend=real-search`，再按运行脚本的实际参数执行。示意模板如下，变量须先赋本轮值：

```bash
: "${RUN_ID:?set a new run ID}"
: "${NEW_BATCH:?set an absolute path to the new manifest}"
cpu_image=df23cd6a9b5b6df30fa003285fadcdc1e5d60919eb43b823b0731c17bf135646
test "$(podman image inspect "$cpu_image" --format '{{.Id}}')" = "$cpu_image"
bash docker/run-cpu.sh "$cpu_image" "$RUN_ID" \
  "$NEW_BATCH" "$RUN_ID-output" http://127.0.0.1:18760
```

这是依照已有入口的复现模板；没有自动执行。先阅读`run-cpu.sh`的网络/挂载选择并核对本机适用性。默认最多5次更新，720/900秒是单请求和屏障保护；无TTT总deadline。原E/F批次并发度为2。新随机种子可能直接零更新解出，也可能未证；如实接受结果，不预置proof或拒绝合法证明制造TTT。

## 重跑本次第1、5题

优先使用这两道已出现多轮后证明成功的题目时，按[04独立复现prompt](04-新agent复现prompt.md)执行。它从本包 `evidence/multiround/raw-evidence.tar.gz` 取出 `inputs/01-CoupledOddSquare.lean`、`inputs/05-CubeAccumulator.lean`，校验后只读挂载到CPU容器。它们不是冻结源码包里的历史 `real-fixtures/`，因此上面的旧 `run-cpu.sh` 示例不能直接只换题名。

重跑时使用新的session、容器和输出卷；输入只带原命题与 `reapTrainingMCTS`，不提供 `proof-check*/` 中的历史答案。收尾时，使用**新运行生成的证明**替换新题搜索入口再独立编译，同时核对新训练回执与新版本调用。历史第1题三轮和第5题两轮成功是复现参考，不保证换seed后仍在相同轮次成功。

## 收尾与错误处理

保存observer、checkpoint、learn请求/回执、树、最终proof、batch配置/solutions和远端HTTP job、快照。对照[03](03-实际TTT结果与证据.md)的门禁复核，不能只看程序的`passed_execution`。

完整成功record且source/profile/config匹配时可跳过；完成结果尚未落到solutions时只核验补record。`manual_intervention_required`、未知mutation或半行输出时先停下，不重发、不restore、不覆盖旧会话。新结果有自己的证据与版本，不继承本次E的成功结论。
