# 真实KL接受与回滚

## 输入、过程与结果

两个独立进程分别使用预先固定的阈值，回放已有真实搜索事件。在试更新之后，程序计算新策略相对冻结基座策略的KL散度，用来检查这次更新是否超出限制。

真实GPU验证覆盖两条路径：较高阈值下接受更新；极低阈值下拒绝更新，并恢复完整私有训练状态。两条路径均通过检查。这证明接受和回滚机制可执行，不表示这些测试阈值已适合大规模训练。

## 核查文件

| 文件 | 核对内容 |
|---|---|
| [accept-report.json](files/accept-report.json) | 接受时参数与版本变化；字段`ok`、`gates`、`schema_version`、`source_sha256` |
| [reject-report.json](files/reject-report.json) | 拒绝后私有状态恢复；字段`ok`、`gates`、`schema_version`、`source_sha256` |

## 原始材料的使用

[manifest.json](manifest.json)记录原始来源、文件大小和SHA哈希；[raw.zip](raw.zip)保存清单内完整原始材料。`files/`提供JSON与Lean文件的阅读副本。需要重新审计或加载训练数据包时，先按清单校验压缩包，再解到新的目录；加载器需要完整数据包，不能仅使用阅读副本。

模型权重、大型适配器及优化器快照、浏览器凭据均未打包。报告中的张量结论来自当时源码已固定的GPU程序，可按哈希追溯；阅读或校验这些文件不会触发训练。
