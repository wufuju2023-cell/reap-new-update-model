# 成功实例与复现检查

## 单题循环：训练后接着原树继续

奇数累加题要求同时证明奇数数列通项与累加平方公式。输入只给命题和条件。搜索进行到第8步时第一次训练，第9步、第10步继续使用更新结果并再次训练，第11步使用第三次更新后的模型完成证明。

实际请求、训练回执和后续生成版本相互对应，最终证明在独立断网Lean环境通过。由此确认：未解题搜索反馈可以进入训练，更新后的模型可以继续支持同一个搜索进程，最终证明可独立核验。

阅读[详细实例](../../docs/current/04-实际实例与验收结果.md#same-tree-three-updates)，按[单题教程](../../reproduction/01-单题TTT.md)重新运行。新运行检查实际发生了几次更新，不把历史“三次”预填进结果。

## 跨题继承：共同起点、各自学习

三道题复制同一份已发布参数，分别建立新的私有状态。立方和题更新4次、带系数三角数题更新1次、等差累加题更新1次后，各自得到通过独立检查的证明。

初始化参数与来源一致，之后各题的更新相互隔离，原经验保持不变。由此确认：一份参数经验可以供多个新题复用，继承不要求各题共用可变训练状态。

原实验最多同时安排两个CPU搜索任务，结束一个后补入第三个；GPU请求由一个服务依次处理。阅读[跨题实例](../../docs/current/04-实际实例与验收结果.md#cross-problem-inheritance)，按[跨题教程](../../reproduction/02-跨题经验复用.md)从本次实际来源重新发布。

## 证明回流：新模型解题，新证明再用于训练

集中训练发布第一版参数后，新题用它证明一个从2开始、每次加3的数列通项。证明独立检查并逐步重放后产生两条训练记录，下一次训练确实读取了它们，并保存、发布第二版参数。

由此确认：模型发布、搜索、证明验证、训练数据加入和后续训练能够接成反馈循环。第二版在该次实验只检查新任务初始化，没有继续解另一道题。见[证明回流实例](../../docs/current/04-实际实例与验收结果.md#proof-training-loop)。

## 双服务并发：两个模型进程分别支持搜索

同一张AMD显卡加载两个独立7B服务，分别处理“自然数等于自身”的证明与“所有自然数等于0”的反证。两题固定使用同一已发布版本，搜索期间不训练，最终都通过独立检查。

两题搜索记录的时间区间重叠约7秒，实际使用了两个服务。由此确认：多服务路由已接入真实Lean搜索。另一个固定请求实验测得约1.93倍并行速度；它测量模型请求，完整解题耗时单独记录。

阅读[双服务实例](../../docs/current/04-实际实例与验收结果.md#parallel-lean-search)，按[多题并发教程](../../reproduction/03-多题并发.md)准备自己的发布版本、两个服务与两题计划。

## 新同学检查自己的实验

一次完整验收需要把输入、执行过程和结果接起来：

1. **输入明确。** 命题、代码、模型版本和CPU环境有记录，搜索输入不包含历史答案。
2. **运行实际发生。** 保留进程、日志、请求回执和实际退出码。
3. **更新与继承可追踪。** 记录训练前后版本、来源参数哈希、新题初始化与后续生成。
4. **证明独立成立。** 在断网CPU容器重新编译完整证明，检查公理依赖。
5. **失败仍可查。** 已知预算耗尽如实记录；请求结果未知时先核查原操作，不重复训练。

完整结果文件和操作命令见[复现检查表](../../reproduction/04-结果检查与故障处理.md)。已有机制测试与真实GPU证据分别保存；本次新电脑实际通过到哪一步，就记录到哪一步。
