# TTT框架：在数学解题过程中学习并复用经验

**本项目的主体是TTT框架：让模型在解题过程中学习，并把学到的经验用于后续搜索和新题。** Reap是我们接入使用的现有树搜索程序，Lean是证明检查器。我们围绕它们实现训练、模型版本更新、跨题经验继承、并发调度和状态恢复。本报告说明截至2026-08-28实际跑通的流程，并提供代码、实验记录和复现方法。

系统接收一道数学命题，由模型（7B，约70亿参数）提出证明步骤，Lean证明检查器判断这些步骤是否正确，Reap搜索程序决定接下来尝试哪个方向。**TTT就是在解题过程中继续训练，让后面的搜索用上刚学到的经验。** 当前保留基础模型的原有参数，只训练少量附加参数，用于改进证明步骤的生成和搜索方向的评价。

## 策略网络和价值网络的分工与学习方式

- **策略网络（policy network）：生成下一步证明动作。** 它根据当前命题、已知条件和待证明目标，生成候选证明步骤，并给出生成这些步骤的概率。题内训练让这些概率学习搜索得到的访问比例；集中训练则让模型学习已经通过检查的证明步骤。
- **价值网络（value network）：评价当前证明状态。** 它读取7B模型对当前证明状态的内部表示，再通过一个小型评价网络给出估值，供搜索程序选择方向。题内训练让估值接近搜索汇总后的评价；集中训练则用已验证证明的步骤数构造评价目标。

**在每个模型服务中，两者共用同一份7B基础模型，价值部分额外接一个小网络。** 训练时基础模型参数保持不变，更新附加参数和小型评价网络。具体怎样在整题尚未成功时获得训练信号，见下方第一条流程。

## CPU和GPU两套环境的分工

- **CPU这套：负责搜索和检查。** 运行Reap与Lean，维护每道题的搜索树，检查候选步骤、安排多题任务、收集搜索反馈，并独立复验最终证明。实际解题时，这套环境不加载7B模型。
- **GPU（显卡）这套：负责模型计算和训练。** 加载7B模型，运行策略网络和价值网络，生成候选、返回估值；收到训练材料后更新参数，并保存或恢复模型状态。

题内学习时，两边这样循环：**CPU发送当前证明状态 → GPU返回候选步骤和估值 → CPU检查并继续搜索 → CPU汇总训练材料 → GPU训练并确认新版本 → CPU接着原来的搜索继续。**

两套环境各有容器构建文件。[CPU容器](docs/08-CPU交付镜像验收.md)已经实际承担搜索和证明复验；[GPU镜像](evidence/current/gpu-runtime-image/README.md)已构建并通过本地检查，当前真实AMD训练运行在远端独立Python环境中，GPU容器内训练尚未验收。

## 已经跑通的流程

下面两条流程分别有实际实验记录。第一条让当前题边搜索边学习；第二条把已验证的证明集中起来训练，供后续题目使用。

### 1. 一道题还没解完，就用本题的搜索反馈继续训练

**提出证明步骤 → Lean检查 → 搜索程序积累反馈 → 更新本题模型 → 确认更新完成 → 接着原来的搜索继续尝试。**

搜索过程中，程序记录哪些候选步骤被反复探索，以及各个方向的搜索评价。这些信息可以在整道题尚未证明时用于训练。更新完成后，同一个Lean进程接着原来的搜索树继续工作，后续生成使用更新后的参数。这个循环按预算重复，直到找到证明或用完预算。

找到完整证明后，再交给一个独立的、断网的Lean检查环境重新验证，确认最终证明有效。

**实际跑通的结果：** [奇数累加得到平方数的实验](docs/current/04-实际实例与验收结果.md#same-tree-three-updates)连续更新三次，每次更新后都接着原来的搜索继续，最终得到通过独立检查的证明。[三角数累加和立方和累加两题](docs/current/04-实际实例与验收结果.md#same-tree-other-proofs)分别经过一次、两次更新后完成证明。实现流程见[题内学习说明](docs/current/01-题内在线TTT.md)。

#### 完整证明之前的训练信号

**整题完成前，最终成功奖励为0；题内训练使用候选访问比例和搜索估值这两类目标：**

- **学习搜索尝试的分配。** Lean先检查候选步骤是否合法；搜索程序综合模型原先的判断、状态估值和探索需要，决定各条路线尝试多少次。训练时把候选步骤的访问次数转成比例，让模型学习这个分配。例如两个候选分别访问8次、2次，就用80%、20%作为训练目标（示意数字）。这个比例反映搜索尝试的分配，包含探索因素。
- **学习搜索后的状态估值。** 对尚未证明的状态，模型先给出一个估计；搜索程序结合后续探索、子目标完成情况和步数，把评价沿搜索树往前汇总，再用于训练模型的评价部分。因此，最终奖励为0时，估值训练目标仍可以非零。估值会有偏差，最终证明仍须通过Lean检查。

**那道“三次更新后证明”的题，第一次训练的真实记录是：** 整题奖励为0，状态估值的训练目标约为0.526；策略部分只有一个被访问的候选`intro n`（引入变量n），训练目标占比为100%。这一轮相当于学习一个已经探索过的合法步骤，同时调整状态估值；0.526是单独的估值目标，最终成功奖励仍为0。随后接着原来的搜索树继续探索、更新，最后得到完整证明。详见[实际训练记录](evidence/multiround/snapshot-audit.json)和[训练目标说明](docs/current/01-题内在线TTT.md)。

### 2. 把已有经验交给新题，并让新证明继续成为训练材料

**保存可复用的模型参数 → 新题复制这份参数开始搜索 → 得到完整证明 → 独立验证 → 加入训练材料 → 集中训练并保存下一版参数。**

新题继承的是已经学到的模型参数。它会建立自己的搜索树、训练记录和临时数据，后续更新不会改动原始经验，也不会影响同时运行的其他题。

集中训练程序使用已经通过验证的证明步骤来学习。本轮还跑通了[两种来源的证明一起训练](docs/current/04-实际实例与验收结果.md#mixed-proof-training)：每批取9条模型生成的证明步骤、1条数学库原有的证明步骤。每条训练记录包含当前证明状态和下一步动作，这里的数量按步骤记录计算。训练后的参数保存为新版本，供后续新题选择。已经开始搜索的题继续使用自己选定的版本；如果采用上一节的边解边训模式，则只更新本题自己的参数。

**实际跑通的结果：** [三道题从同一份经验开始](docs/current/04-实际实例与验收结果.md#cross-problem-inheritance)，各自继续训练并完成证明；[另一组实验](docs/current/04-实际实例与验收结果.md#proof-training-loop)跑通了“新版本解出新题 → 证明通过检查 → 新证明用于下一次训练 → 产生下一版模型”的循环。[保存、恢复后加入新证明继续训练](docs/current/04-实际实例与验收结果.md#continued-learning)也已验证。实现流程见[跨题经验与集中训练](docs/current/02-跨题经验与中央学习.md)。

## 新题的三种经验来源

程序提供三种选择，英文只是配置中的名称：

- **重新开始（fresh）：** 从基础模型开始，不继承之前题目的训练成果。适合需要独立起点的任务。
- **接着指定前题学习（chain）：** 明确指定一份前题已通过验收的经验，新题复制它作为起点。例如要求“题2使用题1学到的参数”，就要等题1的经验准备好，再开始题2。
- **从已有经验库挑选（bank）：** 从已通过验收的经验中，按预先设置的题目分组、标签和优先级选择兼容的一份。当前按照明确规则挑选，尚未实现自动理解题意、寻找相似题的检索。

[三种选择规则已通过本地测试](evidence/current/experience-policy-local/README.md)；[参数实际传给新题、各题互不影响](docs/current/04-实际实例与验收结果.md#cross-problem-inheritance)，已有真实GPU实验。所选经验不存在或不兼容时会拒绝使用；没有匹配来源时默认报错，只有明确允许才退回“重新开始”。

## 多题并行与版本同步

**不同题可以同时搜索，每道题保留自己的搜索树和学习状态。** [双服务真实搜索实验](docs/current/04-实际实例与验收结果.md#parallel-lean-search)在同一张AMD显卡上启动两个独立模型服务，各自支持一道题的Lean搜索；两道题的搜索时间确实有重叠，最终得到的证明和反证分别通过了独立检查。[三题继承实验](docs/current/04-实际实例与验收结果.md#cross-problem-inheritance)还验证了完成题目后释放位置，让后续题目补进来。

同一道难题的不同变体也可以并行。如果明确要求后一个变体使用前一个变体刚学到的经验，就让这两个任务按依赖顺序运行，其他题仍可并行。

采用集中训练时，启用“新任务使用最新版本”后，每次训练完成并确认新版本可用，新开始的任务就可以取用它。正在搜索的任务保持原版本，不必等所有题同时结束再换版本。

**还验证了[服务中断后的模型状态恢复](docs/current/04-实际实例与验收结果.md#published-version-recovery)：** 一次实验完成两轮训练和版本保存后，模型服务因等待超时退出。随后直接恢复旧题的模型状态，让新题使用已保存的新版本，没有重复训练；8项恢复检查全部通过。版本切换规则见[并发与同步说明](docs/current/03-并发调度与模型同步.md)。

[两个模型服务处理同一组固定请求](docs/current/04-实际实例与验收结果.md#parallel-inference)时，测得并行速度约为串行的1.93倍。完整解题流程的长期吞吐量还没有测量。
