# 09。贝叶斯视图：GPU 先验 vs 树外证据源

> 触发问题："这个本质上是 CPU 端改动，但从概率论和贝叶斯角度，它改变了 GPU 侧输出最终 Lean 的概率分布的先验，对不对？"

## 结论先行（精确版）

- "CPU 端改动" ✓ 成立：树外组件，不触碰 GPU 采样函数（RULE-0）；
- "改变先验"：**分为两个时间尺度**——
  - 推理时刻的注入 → 改变的是**后验/条件加权**，θ 不动；
  - 训练回放之后 → θ 更新，**先验迁移**才发生。
- 闭环整体 = 先验确实移动。所以原命题以"闭环终态"理解是对的。

## 概率框架

设 GPU policy：`P(s → t) = P_θ(t | s)`。

| 注入机制 | 数学 | 时间尺度 | 变的是什么 |
|---|---|---|---|
| A. 训练回放（agent 路线入 mixed learner） | θ ← θ′，P_θ′(t\|s) 升高 | 训练步 | **先验** |
| B. 推理时条件（hints：检索到的 lemma/骨架进 context 或 selection 加权） | P(t\|s,R) ∝ P(t\|s)·P(R\|t,s) | 单次推理 | **后验**（RAG 式似然比） |
| C. MCTS selection 层（骨架作为 prior 提升） | π′(a\|s) ∝ π(a\|s)·φ(agent_source)（再与 Q 组合） | 单次搜索 | 搜索先验覆盖 = B 的工程实现 |

## 完整闭环（推荐路线）

```
检索证据 R 来自 Agent Lean 库循环（repo 导航 → lemma 集 → lake build → smoke → 路线库）
    │
    ├─ B 时刻：tree 内 selection 用 P(t|s, R)（骨架/lemma hint）
    │         → 树内先验被证据"取数加权"
    └─ A 时刻：成功路线 + 变体进 replay/mixed learner
              → 下一轮 θ 更新的先验向 R 正例区域移动
```

- 形式上等价于 REAL-Prover 论文的 retrieval-augmented 一脉：检索到的内容成为条件证据，policy 的推理分布被证据 reweight。
- 注意：B/C 不动 θ 的"工厂"——GPU 采样机制保持；受控只在"证据从哪来、何时生效"。

## 唯一风险（贝叶斯意义上的）

- 若检索证据集退化（固定 lemmas、单 session、回放仅一条成功路线）→ P(t\|s,R) 与 P_θ(t\|s) 同收敛到单点 → 先验塌缩（对应用户"只产生一种答案"的担忧，其概率论形态是**分布宽度的缩小，而非生成机制的错**）；
- 反熔设计（RULE-3 + 07 的 session 隔离/Jaccard 门）就是给"证据熵"设下限。

## 在系统里的位置（一句话）

> Agent Lean 循环 = 树外证据源：推理时做似然比加权（后验），训练时把证据变成回放（先验迁移）；MCTS 的 PUCT 中表现为 prior 与 Q 之间额外搭进的"检索证据先验"——即 alpha-style 系统中 knowledge prior 的合法位置。
